# 01 总览

## 1. 背景

Go Minimall 是一套用 Go 实现的电商微服务示例/落地规格项目。目标不是做一个面面俱到的商业 SaaS，而是给出**可按文档开工、可 Docker 本地跑通、可向生产演进**的完整交易链路设计。

典型场景：用户浏览/搜索商品 → 加购 → 用券下单 → 预留库存 → 支付 → 通知与搜索索引更新。

## 2. 目标

- 完整服务域：网关、用户、商品、库存、购物车、订单、支付、优惠券、搜索、通知
- 同步查询 + 异步最终一致性（库存确认、支付结果、通知、索引）
- 统一 API / 错误码 / 幂等 / 可观测约定
- 以 **Docker Compose** 作为开发与演示部署主路径
- 文档规格足以指导第一期实现（接口字段级、表字段级）

## 3. 非目标（本期不做）

- 多租户 SaaS、商家后台完整 OPS、复杂营销玩法（拼团/秒杀专用引擎）
- 真实对接某一家支付/短信 SDK 的生产账号配置（用抽象适配器 + Mock）
- Kubernetes / Service Mesh 作为一期必做项（可在后续附录扩展）
- 完整财务对账、税务、跨境、仓储 WMS
- 前端 App / 小程序（仅约定后端 API）

## 4. 质量属性优先级

| 属性 | 一期要求 |
|------|----------|
| 正确性 | 下单—库存—支付状态机可推导、可幂等 |
| 可运维 | Compose 可启动；健康检查；基础指标与链路 |
| 安全 | JWT 鉴权；回调验签；密钥不入库明文 |
| 性能 | 读多写少路径可加 Redis；热点库存用预留模型 |
| 扩展 | 服务边界清晰；消息契约版本化 |

## 5. 里程碑（摘要）

详细验收见 [13-roadmap.md](13-roadmap.md)。

| 阶段 | 内容 | 验收要点 |
|------|------|----------|
| M0 | 仓库骨架 + Compose 中间件 | MySQL/Redis/NATS 健康 |
| M1 | 用户 + 商品 + 网关 | 注册登录、商品 CRUD、鉴权路由 |
| M2 | 购物车 + 库存 + 订单 | 下单预留库存、取消释放 |
| M3 | 支付 + 优惠券 | 支付成功推进订单、用券核销 |
| M4 | 搜索 + 通知 + 可观测 | 索引同步、事件通知、Prometheus/Grafana |

## 6. 角色与术语

服务职责边界见 [02 架构 · 服务边界](02-architecture.md#3-服务边界一句话)，此处只列领域术语。

| 术语 | 含义 |
|------|------|
| SPU | 标准产品单元（商品） |
| SKU | 库存量单位（规格） |
| 预留 (Reserve) | 下单时锁定库存，未最终扣减 |
| 确认 (Commit) | 支付成功后正式扣减 |
| 释放 (Release) | 取消/超时后归还预留 |
| 幂等键 | `Idempotency-Key`，防重复下单/支付 |
| 领域事件 | 经 NATS 发布的业务事实 |
